# סידור עבודה למלונות: מדריך התקנה

אפליקציית ווב לסידור עבודה ברשת מלונות. עובדים נכנסים מהנייד עם חשבון Google, מצטרפים עם קוד של המלון ומסמנים זמינות. המנהל משבץ, מפרסם ורואה עלויות.

ההתקנה לוקחת בערך 20 דקות, פעם אחת. **את הקבצים מעלה Claude**. אתה רק פותח חשבונות ומעתיק כמה ערכים לשיחה.

---

## שלב 1: פרויקט Firebase (המקום שבו נשמרים הנתונים)

1. נכנסים ל-[console.firebase.google.com](https://console.firebase.google.com) עם kfirdaabul1@gmail.com.
2. **Create a project**, שם: `hotel-shifts`. מבטלים Google Analytics ולוחצים **Create**.
3. **Build ← Authentication ← Get started**. בלשונית **Sign-in method** בוחרים **Google**, **Enable**, בוחרים מייל תמיכה ו-**Save**.
4. **Build ← Firestore Database ← Create database**. מיקום **eur3 (europe-west)**, מצב **Start in production mode**, **Create**.
5. בלשונית **Rules** מוחקים הכל, מדביקים את כל התוכן של `firestore.rules` ולוחצים **Publish**.
6. גלגל השיניים ליד **Project Overview ← Project settings**. ב-**Your apps** לוחצים `</>` (Web), נותנים שם ו-**Register app**.
7. מופיע קטע קוד עם `firebaseConfig`. **מעתיקים אותו כמו שהוא ושולחים לClaude בשיחה.** הערכים האלה לא סודיים. מה שמגן על הנתונים זה כללי האבטחה מסעיף 5.

## שלב 2: GitHub (המקום שבו האתר יושב, בחינם)

1. נרשמים ב-[github.com](https://github.com) אם אין חשבון.
2. **New repository**, שם: `shifts`, **Public**, **Create repository**. לא מעלים כלום.
3. ב-claude.ai: **הגדרות ← Connectors ← GitHub**, מתחברים ונותנים גישה למאגר `shifts`.
4. שולחים לClaude את כתובת המאגר, למשל `github.com/USERNAME/shifts`.

Claude ממלא את `config.js` ומעלה את כל הקבצים למאגר.

## שלב 3: מדליקים את האתר

1. במאגר ב-GitHub: **Settings ← Pages**. ב-Source בוחרים **Deploy from a branch**, ענף `main`, תיקייה `/ (root)`, **Save**.
2. אחרי דקה-שתיים מופיעה הכתובת, למשל `https://USERNAME.github.io/shifts/`.
3. ב-Firebase: **Authentication ← Settings ← Authorized domains ← Add domain**, ומוסיפים `USERNAME.github.io` (בלי `https://` ובלי `/shifts`).

## שלב 4: כניסה ראשונה

1. פותחים את הכתובת ונכנסים עם Google (kfirdaabul1@gmail.com). אתה בעל המערכת.
2. **הגדרות ← ייבוא נתונים**: בוחרים את `import-data.json` מהמחשב ולוחצים **ייבוא**. כל המלונות, העובדים, השכר, המשמרות והסידור עוברים. הקובץ הזה **לא** עולה ל-GitHub, כי יש בו שכר.
3. לכל מלון: בוחרים אותו למעלה, ובהגדרות לוחצים **יצירת קוד** בכרטיס "קוד הצטרפות לעובדים".

## שלב 5: עובדים ומנהלים

- **עובדים:** בסידור לוחצים **שליחה לעובדים**. ההודעה כוללת קישור וקוד הצטרפות.
- **מנהל (למשל טל):** נרשם כמו עובד. אחר כך בלשונית **עובדים** פותחים את הכרטיס שלו, מסמנים **מנהל במערכת** ובוחרים באילו מלונות. הוא מרענן ורואה ממשק מנהל, רק של המלונות האלה.

## שינויים בעתיד

כותבים לClaude בשיחה בפרויקט "תוכנות חדשות" מה לשנות, למשל "באפליקציית הסידור תוסיף…". Claude משנה רק את מה שצריך, מעלה ל-GitHub, והאתר מתעדכן תוך דקה-שתיים. לא צריך להעלות קבצים.

שינוי בכללי האבטחה הוא היוצא מן הכלל: Firebase לא מקבל אותו מ-GitHub. כשזה קורה, Claude אומר לך, ומדביקים את `firestore.rules` מחדש (שלב 1, סעיף 5).

## אבטחה: מה מוגן

- **רק מי שמחובר רואה משהו.** בלי כניסה עם Google אי אפשר לקרוא או לכתוב שום נתון.
- **הרשמה רק עם קוד.** עובד חדש חייב קוד הצטרפות תקף, והקוד קובע לאיזה מלון הוא שייך. עובד לא יכול להעביר את עצמו למלון אחר או לשנות שדות שהם לא הפרטים האישיים שלו.
- **שכר רק למנהלים.** עובדים אף פעם לא רואים שכר, גם לא את שלהם.
- **מנהל רואה רק את המלונות שלו.** שכר, זמינות והגדרות של מלון שהוא לא משויך אליו חסומים בשרת, לא רק במסך.
- **עובד רואה רק את המלון שלו.** פרטי הצוות של מלונות אחרים חסומים.
- **רק בעל המערכת** ממנה מנהלים, מוסיף מלונות ומייבא נתונים.
- **כל השאר חסום כברירת מחדל.**

## עלויות

- **Firebase (Spark):** חינם, מספיק לכמה מלונות עם עשרות עובדים.
- **GitHub Pages:** חינם.
- **כניסה עם SMS (לא חובה):** דורשת חשבון חיוב (Blaze) ב-Firebase ותשלום לכל הודעה. מבקשים מClaude להפעיל.
